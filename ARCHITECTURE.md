# 🏗️ Архитектура системы

## Обзор

Telegram Support Bot - это система поддержки клиентов, построенная на Node.js, TypeScript, Telegraf и Prisma ORM.

## Компоненты системы

### 1. База данных (Prisma + SQLite/PostgreSQL)

```
┌─────────────────────────────────────────────┐
│              База данных                     │
├─────────────────────────────────────────────┤
│                                              │
│  ┌─────────┐  ┌─────────┐  ┌─────────────┐ │
│  │  User   │  │Operator │  │Conversation │ │
│  └────┬────┘  └────┬────┘  └──────┬──────┘ │
│       │            │               │        │
│       └────────────┴───────┬───────┘        │
│                            │                │
│                      ┌─────▼─────┐          │
│                      │  Message  │          │
│                      └───────────┘          │
└─────────────────────────────────────────────┘
```

#### Схема данных:

**User (Клиенты)**
- id: уникальный идентификатор
- telegramId: Telegram ID пользователя
- username, firstName, lastName: информация о пользователе
- isBlocked: флаг блокировки
- createdAt, updatedAt: временные метки

**Operator (Операторы)**
- id: уникальный идентификатор
- telegramId: Telegram ID оператора
- username, firstName, lastName: информация об операторе
- isActive: активен ли оператор
- isOnline: в сети ли оператор
- maxChats: максимальное количество одновременных чатов
- createdAt, updatedAt: временные метки

**Conversation (Диалоги)**
- id: уникальный идентификатор
- userId: ссылка на клиента
- operatorId: ссылка на оператора (nullable)
- status: waiting | active | closed
- createdAt, updatedAt, closedAt: временные метки

**Message (Сообщения)**
- id: уникальный идентификатор
- conversationId: ссылка на диалог
- senderId: Telegram ID отправителя
- senderType: user | operator
- text: текст сообщения (nullable)
- fileId, fileType: информация о файле (nullable)
- messageId: ID сообщения в Telegram
- createdAt: временная метка

### 2. Сервисный слой

#### ConversationService

Управляет жизненным циклом диалогов:

```typescript
class ConversationService {
  // Создание/получение диалога

  // Закрытие диалога

  // Получение списков

```

```typescript
class OperatorService {
```

**Команды операторов:**
- `/start` - панель оператора
- `/queue` - очередь ожидающих

- `/stats` - статистика
- `/online` - войти в сеть
- `/offline` - выйти из сети
- `/done` - завершить текущий диалог
- `/cancel` - отменить режим ответа

### 4. Система распределения

#### Алгоритм назначения оператора:

```
Новое обращение
      │
      ▼
┌─────────────────┐
│ Найти всех      │
│ онлайн          │◄───── isActive = true
│ операторов      │       isOnline = true
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Отфильтровать   │
│ по лимиту       │◄───── activeChats < maxChats
│ активных чатов  │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Сортировка по   │
│ количеству      │◄───── Меньше чатов = выше
│ активных чатов  │       приоритет
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Взять первого   │
│ из списка       │
└────────┬────────┘
         │
         ▼
   Назначить оператора
```

Если нет доступных операторов:
- Диалог остается в статусе `waiting`
- Когда оператор освободится, система попытается назначить его автоматически

#### Балансировка нагрузки:

Система автоматически распределяет нагрузку между операторами:

```
Оператор 1: ████░░░░░░ (4/10 чатов)  ◄─── Получит следующий
Оператор 2: ██████░░░░ (6/10 чатов)
Оператор 3: ██████████ (10/10 чатов) ◄─── Занят
Оператор 4: Offline    ◄─── Не получает
```

### 5. Жизненный цикл диалога

```
┌─────────────┐
│   waiting   │◄───── Клиент написал первое сообщение
└──────┬──────┘
       │ assignOperator()
       ▼
┌─────────────┐
│   active    │◄───── Оператор назначен
└──────┬──────┘       Идет переписка
       │ closeConversation()
       ▼
┌─────────────┐
│   closed    │◄───── Диалог завершен
└─────────────┘
```

**Переходы состояний:**
- `waiting` → `active`: оператор назначен
- `active` → `closed`: оператор завершил диалог
- `waiting` → `closed`: диалог закрыт без ответа (администратор)

### 6. Контекст оператора

Для удобства работы операторов используется контекстная система:

```typescript
// Map: telegramId -> conversationId
const operatorContext = new Map<string, number>();
```

**Как работает:**
1. Оператор берет диалог в работу → устанавливается контекст
2. Все последующие сообщения отправляются в этот диалог
3. Оператор может переключиться на другой диалог → контекст обновляется
4. Завершение диалога → контекст очищается

**Преимущества:**
- Не нужно постоянно выбирать диалог
- Быстрые ответы
- Интуитивный workflow

### 7. Система уведомлений

#### Для клиентов:

```
Event                    Notification
─────────────────────────────────────────
Первое сообщение    →    "Ожидайте оператора"
Оператор подключен  →    "Оператор подключился"
Новое сообщение     →    "[Текст от оператора]"
Диалог закрыт       →    "Диалог завершен"
```

#### Для операторов:

```
Event                    Notification
─────────────────────────────────────────
Новое обращение     →    Уведомление с кнопкой "Взять"
Новое сообщение     →    Текст + кнопки "Ответить/Закрыть"
Диалог взят         →    История сообщений
```

### 8. Обработка ошибок

```typescript
try {
  // Операция
} catch (error) {
  console.error('Error:', error);

  // Пользователь
  await ctx.reply('❌ Произошла ошибка');

  // Не прерывать работу бота
}
```

**Принципы:**
- Все ошибки логируются
- Пользователь получает понятное сообщение
- Бот продолжает работу
- Критические ошибки прерывают запуск

### 10. Производительность

**Оптимизации:**
- Индексы в БД на часто используемые поля
- Лимиты на количество сообщений в истории
- Асинхронная обработка уведомлений
- Кеширование часто используемых данных (операторов)

**Узкие места:**
